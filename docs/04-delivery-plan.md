# MVP 实施路线图

## 阶段 1：范围冻结

目标：
- 把首版能力锁定在最小可用范围

产出：
- MVP 范围清单
- 核心分析维度
- DDD 分层说明
- 接口草案
- 数据库草案

## 阶段 2：主链路打通

目标：
- 先让任务可以跑通

产出：
- 视频上传
- 任务创建
- 任务状态查询
- 异步执行框架
- 结果查询

## 阶段 3：预处理链路

目标：
- 把视频变成可分析的领域输入

产出：
- 抽帧
- ASR
- 基础元数据
- 结果落库

## 阶段 4：诊断链路

目标：
- 先做最关键的三个维度

产出：
- Hook
- Structure / Rhythm
- Value Delivery
- Finding 输出

## 阶段 5：稳定性

目标：
- 让结果可重复、可追踪、可恢复

产出：
- 幂等
- 重试
- 缓存
- 版本快照
- Coverage Guard

## 阶段 6：验收

目标：
- 验证结果是不是“真有用”

产出：
- 20~50 组样例
- 人工标注
- 简单对比评估

## DDD 优先顺序

1. 先定领域对象和核心用例
2. 再定应用层用例编排
3. 再定接口协议
4. 再定基础设施实现
5. 最后做优化和扩展

## 小傅哥式落地原则

- 先把一个完整用例打穿
- 再逐步抽离通用能力
- 不要一开始就把结构做得很重
- 先保证边界清晰，再追求扩展性
