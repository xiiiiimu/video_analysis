# 16. 诊断质量规则 v2 + mock 评测

第一次真实运行（my.mp4 vs ref1.mp4）暴露的问题，以及对应的修改：

| 问题 | 原因 | 修改 |
|---|---|---|
| `findingType` 全是 `unknown` | `result_contract` 把白名单外的类型静默改成 unknown | 新分类表 `graph/finding_types.py`；v2 下不再静默改写，类型不合法由 Evaluator 带允许列表打回 |
| 钩子说"开场没有价值承诺"，价值传递却说"第 3 秒就传达了收益" | 冲突检测只认"加快/放慢"这类对立动词 | 跨维度矛盾检查：钩子判 `hook_no_value_promise` 而价值传递引用了开场 5 秒内的收益原文 → 打回钩子专家并附上对方的原文（反向同理） |
| "目标比参考做得好"被标成 P0 问题 | 没有方向的概念，所有结论都当问题 | 结论增加 `polarity`：GAP / STRENGTH / PARITY；只有 GAP 进入改进优先级和 Finding 落库，优势 / 相当写进 `synthesis.strengths / parity` |
| 结论空泛，引用全是机械的帧时间点 | 模型看不到画面，帧引用不提供信息 | 每条结论必须有 `quotes`（逐字摘抄口播 / 屏幕文字），系统校验原文真实存在（忽略标点，时间允许 ±3 秒，ref 写错会自动修正）；结构节奏可以改用 `SCENE` 镜头数据 |
| synthesis 排名与 Java 结果的 P0/P1 对不上 | Java 按置信度 ≥0.85 自行判 P0 | agent 按合成排序下发 `priority`（第 1 名 P0、第 2 名 P1、其余 P2），Java 优先使用 |
| 结果接口 `missingInputs: ["video_feature"]` 误报 | 与证据为空同一个原因：特征以 AUTO_FRAME 保存 | 按任务查不到时按目标视频查 |

另外：视频被截断（超过分析窗口）时，不允许断言"结尾没有行动号召"；`PARITY` 结论不因置信度低被反复打回。

## 开关

`QUALITY_RULES=v2`（默认）/ `v1`（改造前行为，只用于评测对比）。docker-compose 里已加该变量。

## mock 评测

`agent_service/eval/quality_cases.py`：15 组构造的证据包（与 Java `/evidence` 接口格式一致），每组预埋已知问题：

| 类型 | 样本 |
|---|---|
| 开场钩子 | c01 无价值承诺、c02 空镜慢启动、c11 矛盾诱饵（口播有承诺但无字幕）、c13 截断长视频 |
| 结构节奏 | c06 / c15 切换过密、c07 一镜到底、c08 无步骤标记 |
| 价值传递 | c03 收益太晚、c04 无行动号召、c05 无结果证明、c12 转写失败只有字幕 |
| 误报对照 | c09 目标开场更强、c10 目标价值传递更强、c14 两者几乎一致 |

指标全部按规则判定（不用 LLM 打分）：预埋问题命中率、误报率、优势被当成问题的比例、带原文引用的结论占比、
类型在分类表内的占比、无效引用占比、多次运行一致性、平均打回次数 / token / 耗时。

运行（在容器里，需要真实 key，约 15~30 分钟、几十万 token）：

```
docker compose exec agent-service python -m agent_service.eval.quality_benchmark --rules v1,v2
docker compose exec agent-service python -m agent_service.eval.quality_benchmark --rules v2 --repeat 3
docker compose cp agent-service:/tmp/quality-reports ./benchmark-reports/quality
```

**局限**：mock 只衡量诊断逻辑，测不了 OCR / ASR / 镜头检测质量，也不代表真实视频上的准确率；
v1 没有分类表，按"维度 + 关键词"匹配，命中和误报都偏宽松，对比时以 v2 的数字为准。
真实视频的对照集（3~5 组，人工写下关键问题）需要另外准备。

## 第二轮调整（第一次真实评测之后）

第一次 v1/v2 对比：误报率 50%→0%、优势误报 100%→0%、原文引用 14%→88%，但命中率 58%→42%。
逐组查看后发现漏报主要来自**弃权过多**（结构节奏 15 组弃权 11 组），而不是没看出问题：

| 原因 | 调整 |
|---|---|
| 输出示例 `"confidence": 0.0` 被模型照抄 → 低于阈值被打回 → 打回提示里有"证据不足时改为 ABSTAIN" → 直接弃权 | 示例改为 0.75 并给出分段含义；v2 的打回提示改为"补证据 / 如实打分 / 差异不明显用 PARITY，证据存在时不要 ABSTAIN" |
| 模型把 `00:01:05` 读成"第 5 秒"，还会编出 `01:05:12` 这种引用 | 证据分段直接给出秒数 `s="65-72"` 和可复制的 `ref` |
| 结构维度要模型自己从几十个镜头里数数 | 系统预先计算 `sceneStats`（镜头数、平均/中位/最长镜头、2 秒内短镜头数、每 30 秒切换次数），引用 `METADATA:T` 即视为有证据 |
| 转写失败时三个维度全部弃权 | 明确：没有口播也要依据屏幕文字和镜头数据下结论，只降低置信度 |
| 评测看不到弃权和中间轮次 | 新增弃权占比；记录每一次专家调用（含打回后的重写）和每轮评估原因；打回次数不再显示成百分比 |

## 第三轮调整（第二次评测之后）

第二次评测：命中率 92%、弃权 0%、一致性 98%，但误报 12%、优势被当成问题 100%。查看每一轮输出后确认：
模型**没有把目标和参考搞混**（引用都正确），而是 ① 孤立地给目标挑毛病，没有真正和参考比较——目标与参考开场一字不差也判 GAP；
② 概念理解过窄——"三个技巧，让你的早餐五分钟就能做好"不算价值承诺、开场承诺不算"收益首次出现"。两个专家错得一致，矛盾检查拦不住。

| 调整 | 说明 |
|---|---|
| 方向由评分计算 | 模型必须给目标和每个参考打 1~5 分；目标比最好的参考低 ≥1 分才是 GAP，高 ≥1 分是 STRENGTH，否则 PARITY。与模型自报方向不一致时以评分为准，记录在 `polarity_overridden` |
| 差距必须有参考证据 | GAP 结论的 quotes 必须包含参考视频（R1/R2）的原文；结构节奏可以引用 `METADATA:R1` / `SCENE:R1#n` |
| 证据相同不能判差距 | 目标与评分最高的参考开场 5 秒文字相似度 ≥0.9 却判 HOOK 差距 → 打回；平均镜头时长差异 ≤15% 却判节奏过快/过慢 → 打回 |
| 概念定义 + 正反例 | 价值承诺 / 收益首次出现 / 行动号召给出可操作定义；示例刻意使用与评测样本不同的话题（修图、Excel），避免"背答案" |
| 结构建议带数字 | 结构节奏的 GAP 建议必须写出目标与参考的镜头数据和建议值 |
| 评测集扩充到 19 组 | 新增健身（开场优势）、理财（收益太晚）、修图（开场相同 + 切换过密）、英语（价值传递优势）四个不同话题 |

## 第四轮调整（第三次评测之后）

第三次评测（19 组）：优势被当成问题 100%→0%，命中率 86%，误报 12%。剩余误报集中在"目标与参考内容几乎相同"的样本，原因：

1. **打回用尽后违规结论照样放行**：c14 / c17 的"镜头统计一样却判节奏差距"连续被打回 2~3 次，模型始终不改，最后以 GAP 过关；
2. **模型的结论与它自己的观察矛盾**：c18 观察写"第 0.4 秒就说出收益承诺"，结论却是 value_late；c11 观察里列出了"第一步/第二步/第三步"，结论却是 structure_unclear；
3. **c02 是类型选错**：开场 6 秒空镜，判对了"开场有问题"，类型却选成 hook_no_value_promise。

| 调整 | 说明 |
|---|---|
| 硬规则 + 打回用尽后强制降级 | `hard_rule_violation`：开场文字相同 / 开场口播相同却判"没有价值承诺" / 平均镜头差异 ≤15% 却判节奏差距 / 已有分段标记却判 structure_unclear / 收益并不比参考晚却判 value_late。先打回；打回用尽仍违反 → 降级为 PARITY，记录在 `downgraded`，出现在 `synthesis.parity` |
| `first_benefit_seconds` | VALUE 专家必须填写各视频首次说出收益的秒数；目标比参考晚不到 3 秒不能判 value_late |
| 可计算的事实由系统判定 | 目标开场 5 秒没有任何口播和字幕 → 类型直接改为 hook_slow_start（`type_corrected`） |
| 解析容错 | 模型输出字符串代替列表、列表里夹 null 时规整，不再导致专家执行失败 |
| 评测可见性 | 记录模型给的分数、`first_benefit_seconds`、专家执行失败原因；汇总"评分改写方向 / 改写类型 / 降级 / 执行失败"次数 |

## 第五轮：hard 评测组 + 账户错误直接终止（模型对比之前）

| 样本 | 难点 | 期望 |
|---|---|---|
| c20 收纳 | 收益"整齐很多"vs"多放一倍"——细微差距；开场两者相同 | value_unclear；不判开场 |

| c24 护肤 | 一个视频两个问题 | hook_slow_start + no_proof |

**账户错误直接终止**：第一次跑 gpt-5.6-terra 时余额用完，429 被当成限流重试，专家失败后弃权，run 仍然显示 success，
评测把空结果算成漏报。现在 `ModelRetryPlugin` 遇到 401 / 402 / 余额不足的 429（insufficient_quota、no credits 等）
不再重试，直接以 `stop_reason=model_fatal` 停止整个 run（真实任务回调 Java 时错误信息带 `[model_fatal]`）；
评测遇到后立即中止，报告标记"已中止"。普通限流的 429 仍然重试。报告里新增服务商（base URL 的域名）。

## 第六轮：评分点检索（RAG）接入主流程

核对发现：从最初版本起，检索只在任务上下文带 `category / needKnowledge / useKnowledge` 时触发，而 Java 从不传这些字段，
所以**此前所有真实任务和质量评测都没有经过 RAG**；运行时挂的也只是 6 条通用原则，34 条评分点只用于检索评测。
另外即使触发，检索结果也只是作为引用挂在结论上，**没有交给模型**。

| 修改 | 说明 |
|---|---|
| 评分点知识库 | 运行时改用 34 条评分点（`diagnosis_rubric_corpus()`，与检索评测 v0.3 同一份内容） |
| 每次必检索 | `RAG_MODE=always`（默认）：每个维度专家下结论前先检索本维度评分点（`RUBRIC` 类型 = 该维度全部知识类型），top-k=`RUBRIC_TOP_K`（默认 6） |
| query 随视频变化 | 维度关注点 + 目标视频特征：开场有没有信息 / 有没有收益词、镜头是否长期不变或切得很碎、有没有分段标记、结尾有没有行动号召、有没有结果证明 |
| 交给模型 | 评分点（ref / 类型 / 标题 / 判定重点）放进模型输入的 `rubric`；提示词要求逐条对照并在 `rubric_refs` 注明依据 |
| 校验 | 只保留确实检索到的评分点作为结论的知识依据；Evaluator：没注明依据 / 引用了没检索到的评分点 → 打回。知识库不可用时不强制 |
| 评测 | `--rag on,off` 对比有 / 无评分点检索；新增"结论注明依据评分点的占比"；所有比例同时给出分子 / 分母 |

`RAG_MODE=off` 保留改造前的行为，只用于对比。

## 第七轮：RAG 消融 + rag 题组

**2×2 消融**（deepseek-flash，基础 + 难题 + 标准组共 28 组 × 2 次，误报全部 0/182）：

| 预埋问题命中（/46） | RAG 开 | RAG 关 |
|---|---|---|
| full（提示词写死概念定义） | 44 | 43 |
| lite（`PROMPT_PROFILE=lite`，去掉定义） | 45 | 46 |

差异都在 c24 / c25 的随机波动内。结论：这套题的预埋问题都是通用常识，模型不需要定义也不需要检索就能答对，
测不出 RAG 的作用；RAG 在这里的价值是可追溯（结论 100% 注明依据的评分点）和标准可维护，代价 token +13%。

**rag 题组（r01~r23）**：正确答案依赖某条具体评分点，测"没有检索时能不能判对"。
- A 类 15 道：通用评分点里的边界 / 反直觉规则（权威背书后马上接收益不算铺垫、喊人群标签不接收益不算钩子、
  具体的反问悬念算钩子、长镜头 + 密集字幕不算拖沓、屏幕编号算段落标记……），多数成对出现（例如 r01 / r02）；
- B 类 6 道：知识教程品类的私有规范（`knowledge/rubric/private_edu.md`，`category: 知识教程`），模型不可能事先知道；
- 对照 2 道（r17 / r21）：与 B 类证据相同但不带品类，私有规范不应生效。
- 每题写明依赖的评分点（depends_on）；新增指标"依赖的评分点被检索到 / 被引用"。离线检查：23 道题依赖的评分点全部能被检索到。

为此做的改动：
- 评分点支持 `category`（品类专属，只对同品类任务生效，检索时全部带上不参与排序）；一个文件可以 `skill: mixed`；
- 创建任务可传 `category`（JSON 字段 / 上传接口参数），写入输入快照；
- 检索 query 增加开场 / 正文的写法信号（自我介绍、反问、点名人群、堆参数、前后对比、冲突、空泛说法），
  否则边界类评分点检索不到。

运行（lite 提示词，开 / 关 RAG）：
`python -m agent_service.eval.quality_benchmark --rules v2 --prompt lite --rag on,off --repeat 2 --cases rag`

结论：
1. **通用常识类判断**（基础 / 难题 / 标准组）开不开 RAG 结果差不多：模型本来就懂，加上有参考视频对比。准确率提升不能算 RAG 的功劳。
2. **RAG 的作用在两类规则上**：模型事先不可能知道的**私有 / 用户规范**（r18），和与模型直觉相反的**边界规则**（r09）。
   附带价值是可追溯（结论 100% 注明依据的评分点）和可维护（改 md 就改判定，不改代码和提示词）。
3. **题目设计的局限**：系统做的是"目标 vs 参考"的比较，只要参考按规则做了，答案就摆在面前。
   要更干净地测 RAG，应该出"反向题"：参考按通用直觉做得好但违反私有规范，目标遵守私有规范——只有检索到规则才能判对。尚未做。
